На одном origin сессия разделяется с Mini Budget, Tattoo Finance, Конвертами и CRM. До подтверждения владельца финансовый интерфейс и рабочие скрипты закрыты. Email/Password не используется.

Первый запуск после входа открывает облако: `budgetControl/{ownerUid}`. Существующие локальные записи сохранены и не импортируются автоматически. Настройки позволяют открыть данные этого браузера отдельно; ранее выбранный локальный режим восстанавливается после входа. Облачные расходы автомобиля и доходы студий читаются из прежних путей; оригиналы не изменяются и не копируются.

`users/mini/expenses` — автомобиль, `incomes` — доходы Tattoo Finance. Неизвестные категории видны как расходы вне плана. Ошибки источника и неполный кеш не считаются нулевыми расходами. Профессиональные расходы отключены в версии 1.0 согласно первоначальной спецификации; подготовленный адаптер исключает транспорт только при агрегировании, не в Tattoo Finance.

Закрытие месяца сохраняет снимок плана. Регулярный платёж создаёт расход либо связывает существующий, защищён от повторного подтверждения и сохраняет календарный якорь. Среднее требует 12 полных месяцев подтверждённой истории. Экспорт содержит только собственные данные приложения.

**Рабочие Firestore Rules пока публичные и не изменены.** Кандидат `../firestore.rules` прошёл локальные проверки. Его нельзя публиковать до проверки настоящего Google-входа владельца во всех приложениях и на используемых устройствах. Полный аудит, права, домены, ограничения iOS и порядок выпуска — в [FIREBASE-AUDIT.md](../FIREBASE-AUDIT.md).

## Локальный просмотр

Из корня репозитория:

```sh
node budget-control/dev-server.mjs
```

Открыть `http://localhost:4173/mini-budget-app/budget-control/index.html` для настоящего Google-входа: localhost уже разрешён в Firebase. Данные живого проекта загружаются только после входа владельца. Preview через `file://` не поддерживается.

## Проверки

```sh
cd budget-control
npm install
npm test
npm run test:rules
```

Для правил нужна Java 21. Для интеграционных браузерных тестов отдельно запустить `npm run test:emulators`; затем сервер из корня с переменной **AUTH_TEST_MODE=1**. Это меняет только ответы локального сервера, включая fetch service worker, на `demo-budget-control`. Тестовая конфигурация не входит в опубликованные HTML.

В PowerShell:

```powershell
$env:AUTH_TEST_MODE='1'
node budget-control/dev-server.mjs
```

В другом терминале: `npm run test:auth` (Google popup, общая сессия, облако, выход и отказ), `npm run test:browser` (локальный учёт после тестового Auth, формы, 60 проверок экранов на движок, офлайн). Для WebKit установить браузер Playwright и задать `BROWSER_ENGINE=webkit`. При необходимости `PLAYWRIGHT_MODULE` указывает на установленный модуль, `PLAYWRIGHT_BROWSERS_PATH` на его браузеры.

Тесты Auth/Firestore работают только с локальными эмуляторами и `demo-*` project ID. Другие origins не разделяют сессию; установленный iOS PWA может иметь отдельное хранилище от Safari. Полная физическая проверка перед выпуском обязательна. Подробные результаты — в [VERIFICATION.md](./VERIFICATION.md).
